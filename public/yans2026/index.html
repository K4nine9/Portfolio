💬 発表者用 想定Q&A集（対話・質問対策カンペ）
最頻出 Q1. なぜ1段階RAGではなく3段階パイプラインにする必要があるのか？
⚡ 単段RAG（48.0%）は検索なし（47.6%）と大差なく、検索ノイズによる混乱と制約崩壊を起こすため。
  • 「多角的エビデンス収集（発散）」と「280文字圧縮・中立化（収束）」を1プロンプトで行うと注意散漫になる
  • 「①調査レポート（事実の抽象化）」➔「②初稿起草」➔「③プログラム監査添削」にタスク分離することが不可欠
単段RAG: 48.0% レポート導入: 56.0% (+8.0pp) 自己添削導入: 71.0% (+15.0pp)
最頻出 Q2. LLM-as-a-Judge の評価結果は信用できるのか？ 人間とズレていないか？
⚡ 4名の日本人評価者によるブラインド人間評価で Close Match率 90.0%、Pearson r = 0.7105 と高い一致度を実証済み。
  • 人間と同一の5段階ルーブリックを与え、最新事象の誤判定防止のため動的Web検索を義務付け
  • 特に Grok や OpenAI では人間との Close Match 率は 100.0%（MAE 0.2〜0.6）と極めて安定
Close Match (差1以内): 90.0% Pearson 相関: r = 0.7105 MAE: 0.6500
前提条件 Q3. 理由タグ（misleadingFactualError等）はどう与えているのか？ 自律推定は？
⚡ 本稿はタグ所与の高品質生成に特化したが、補助実験の分類器で 82.93% の精度で自動推定可能。
  • 生ツイートから理由タグを推定するモジュールで Any-match Accuracy 82.93% / F1 56.70% を達成
  • 本手法と連結することで、生ツイートからノート完成までの完全自律End-to-End化が可能
重要インサイト Q4. なぜ検索特化の Sonar が 17% で、Grok が 87% と圧倒的なのか？
⚡ ボトルネックは「検索力」ではなく、280文字やURL形式を守る「推論・指示追従力」にあるため。
  • Sonar (17.0%): 検索力はあるが [1][10] 等の内部記号を出力し文字数無視でダンプ（45%がScore 1）
  • Grok-4.5 (87.0%): Xドメインに適合し、法的なニュアンスとデマを推論で切り分け Score 0 が 0.0%

⚡ Stage 3 の実アクセス監査ループが検知し、全201件（100%）を公的直接URLへ自動置換。
  • 初稿で40.20%混入した vertexaisearch... などの不透明URLを100%正規化
